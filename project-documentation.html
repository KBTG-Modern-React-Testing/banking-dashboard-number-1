01 — Overview

ภาพรวมโปรเจกต์

Modern Banking Dashboard เป็น Single-Page Dashboard ที่สร้างด้วย Next.js 16 (App Router) สำหรับตรวจสอบยอดเงินในบัญชี ดูประวัติธุรกรรม และทำรายการโอนเงิน โดยใช้ธีม Dark Mode เป็นค่าเริ่มต้น ตามแนวทาง xAI-Inspired Design System ที่เน้นความเรียบหรูด้วยพื้นหลังสีดำเข้ม (near-black) พร้อมปุ่มทรง Pill สีขาว

💰 Balance Card

แสดงยอดเงินคงเหลือในบัญชี USD แบบ Real-time พร้อม Gradient Accent Line และ Loading Skeleton

📋 Transaction List

รายการธุรกรรมทั้งหมดพร้อม Filter ตามสถานะ (All / Pending / Completed / Failed) และ Status Badge

💸 Transfer Form

ฟอร์มโอนเงินพร้อม Client-side Validation, Error handling และ Success animation feedback

🎨 Theme Toggle

สลับ Dark / Light mode ด้วย Data-attribute theming บันทึกค่าลงใน localStorage

04 — Components

React Components

ทุก Component เป็น Client Components ("use client") เนื่องจากต้องใช้ React hooks สำหรับ state management, events และ effects

ThemeProvider

context hook

จัดการ Dark / Light theme ผ่าน React Context

  • ใช้ data-theme attribute บน <html>
  • บันทึกค่าลง localStorage (key: banking-theme)
  • Export useTheme() custom hook
  • ค่าเริ่มต้น: dark

DashboardContext

context api

State Management กลางของ Dashboard — จัดการ balance, transactions, filters

  • balance — ยอดเงินปัจจุบัน
  • transactions[] — รายการธุรกรรม
  • activeFilter — ฟิลเตอร์ที่เลือก
  • addTransaction() — POST ไปยัง API
  • Export useDashboard() hook

NavBar

ui responsive

แถบนำทางด้านบน — Sticky, Blur backdrop

  • Brand logo (Accent dot + "BANKING")
  • Theme toggle button (Sun/Moon icons)
  • Mobile hamburger menu (≤ 767px)
  • ใช้ styled jsx สำหรับ responsive

BalanceCard

ui animated

แสดงยอดเงินคงเหลือในบัญชี

  • Sunset gradient accent line ด้านบน
  • Skeleton loading (pulse-glow animation)
  • จัดรูปแบบตัวเลขด้วย Intl.NumberFormat
  • Decorative radial gradient glow

TransactionList

ui filter

รายการธุรกรรมพร้อม Filter + Loading skeleton

  • Sub-components: StatusBadge, StatusIcon, TransactionRow
  • Staggered animation delay ต่อแถว
  • Empty state สำหรับ 0 รายการ
  • Date/Currency formatting ด้วย Intl

TransactionFilters

ui

ปุ่ม Pill สำหรับ Filter ธุรกรรมตามสถานะ

  • ตัวเลือก: All / Pending / Completed / Failed
  • Active state: filled pill (สีสลับ)
  • ใช้ aria-pressed สำหรับ accessibility

TransferForm

form validation

ฟอร์มโอนเงิน พร้อม Validation + Error/Success feedback

  • Fields: Amount (number), Recipient (text), Description (optional)
  • Client-side validation ก่อน submit
  • aria-invalid สำหรับ accessibility
  • Loading spinner (Loader2 icon) + success toast
  • Clear form อัตโนมัติหลัง transfer สำเร็จ

Button (ui/button)

shadcn cva

Base Button component จาก shadcn/ui

  • ใช้ class-variance-authority สร้าง variants
  • Variants: default, destructive, outline, secondary, ghost, link
  • Sizes: default, sm, lg, icon
  • ใช้ Slot จาก Radix สำหรับ asChild pattern

🏗️ Component Hierarchy

// Component tree ของหน้า Dashboard <ThemeProvider> <DashboardProvider> <div> // root container <NavBar /> // sticky nav + theme toggle <main> // max-width 1200px centered <div class="dashboard-grid"> // CSS Grid: 2 columns <div> // Left column (380–420px) <BalanceCard /> <TransferForm /> </div> <div> // Right column (fluid) <TransactionList> <TransactionFilters /> <TransactionRow /> // × N items </TransactionList> </div> </div> </main> <footer /> </div> </DashboardProvider> </ThemeProvider>

06 — API Routes

API Route Handlers

ใช้ Next.js Route Handlers (App Router) สำหรับ API — ข้อมูลถูกเก็บใน In-Memory Store (ไม่มี Database) เหมาะสำหรับ Demo และ Development

MethodEndpointResponseรายละเอียด
GET /api/balance { balance: 15000.5, currency: "USD" } คืนค่ายอดเงินคงเหลือ (hard-coded $15,000.50)
GET /api/transactions { transactions: [...] } คืนรายการธุรกรรมทั้งหมด เรียงตาม createdAt ล่าสุดก่อน (7 seed records)
POST /api/transactions { transaction: {...} } สร้างธุรกรรมใหม่ — Validate: amount (>0, number), recipient (required) → Status 201

📦 Transaction Data Model

interface Transaction { id: string; // "txn_001", "txn_002", ... amount: number; // จำนวนเงิน (USD) currency: string; // "USD" status: "Pending" | "Completed" | "Failed"; description: string; // คำอธิบายธุรกรรม recipient?: string; // ชื่อผู้รับ (optional ใน GET) createdAt: string; // ISO 8601 datetime updatedAt: string; // ISO 8601 datetime }
07 — State Management

State Architecture

ใช้ React Context API 2 ชั้น แยกความรับผิดชอบ — ไม่ใช้ External State Library (Redux, Zustand)

ThemeContext

จัดการ UI theme ทั้งแอป

interface ThemeContextValue { theme: "dark" | "light"; toggleTheme: () => void; }
  • Persist ผ่าน localStorage
  • Sync ด้วย data-theme attribute
  • Wrap ทั้ง app ใน <ThemeProvider>

DashboardContext

จัดการ Business logic + Data fetching

interface DashboardContextValue { balance: number; transactions: Transaction[]; filteredTransactions: Transaction[]; activeFilter: FilterStatus; isLoading: boolean; setFilter: (f) => void; addTransaction: (p) => Promise; }
  • Fetch balance + transactions จาก API เมื่อ mount
  • Client-side filtering
  • Optimistic UI update เมื่อ POST สำเร็จ

08 — Testing

Testing Setup

ใช้ Vitest + React Testing Library สำหรับ Unit / Integration tests ทดสอบทุก Component หลักที่มี Logic ซับซ้อน

⚙️ Test Configuration

// vitest.config.mts export default defineConfig({ plugins: [tsconfigPaths(), react()], test: { environment: "jsdom", // จำลอง DOM ใน Node.js setupFiles: ["__tests__/setup.ts"], // Global mocks css: false, // ไม่ process CSS ใน tests }, });

🧰 Test Setup (Global Mocks)

  • cleanup() — Auto-cleanup React DOM หลังทุก test
  • localStorage mock — จำลอง localStorage API (getItem, setItem, removeItem, clear)
  • fetch mock — global.fetch = vi.fn() สำหรับ mock API calls
  • IntersectionObserver mock — จำลอง browser API ที่ไม่มีใน jsdom
